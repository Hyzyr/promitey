## ✅ Сделано

### 1. Ввод кода подтверждения на iOS / мобильных
**Проблема:** появлялась цифровая клавиатура, но нажатия цифр не заполняли поля — ввод «зависал».

**Решение** — [`verification-code-input.tsx`](../src/ui/auth/components/verification-code-input.tsx)
- Убран `maxLength={1}` — он «съедал» нажатия на iOS, когда поле уже заполнено (основная причина «ничего не происходит»).
- Добавлен `onFocus` → `select()`: при тапе по заполненному полю содержимое выделяется и ввод перезаписывает его корректно.
- Добавлено распределение нескольких цифр: когда автозаполнение iOS `one-time-code` или вставка приходят пачкой, цифры раскладываются по полям.
- `autoComplete="one-time-code"` теперь только на **первом** поле (iOS глючит, если он на всех 6); добавлен `pattern="[0-9]*"`.

### 2. Скачок размера кнопки при загрузке
**Проблема:** в состоянии загрузки контент заменялся маленьким спиннером, и кнопка меняла размер (глитч), особенно кнопки-иконки.

**Решение** — [`button.tsx`](../src/components/ui/button.tsx)
- Дочерний контент остаётся в DOM, но становится невидимым, а спиннер накладывается поверх (absolute).
- Ширина/высота кнопки одинаковы в покое и при загрузке. Применено к `Button` и `GlassButton`.

### 3. Переполнение текста в кнопке
**Проблема:** длинная надпись «Активировать пробный период» вылезала за карточку подписки.

**Решение** — [`subscription-card.tsx`](../src/ui/dashboard/pages/subscription/subscription-card.tsx), [`trial-activation-button.tsx`](../src/ui/dashboard/pages/subscription/trial-activation-button.tsx)
- Кнопки действий теперь на всю ширину и складываются столбцом на мобильных (`flex-col` → `sm:flex-row`). У кнопки пробного периода на мобильных используется короткий текст («Попробовать»), а полный текст остаётся на больших экранах.

### 4. Убрана сомнительная / платная рекомендация клиента
**Проблема:** в инструкции рекомендовался **Shadowrocket** (платное iOS-приложение).

**Решение** — заменён на **Hiddify** (бесплатный, open-source):
- [`instructions-tabs.tsx`](../src/ui/dashboard/pages/instructions/instructions-tabs.tsx) (ссылка → `https://github.com/hiddify/hiddify-app`)
- [`messages/en/dashboard.json`](../messages/en/dashboard.json) и [`messages/ru/dashboard.json`](../messages/ru/dashboard.json) (название приложения + список источников)
- Остальные клиенты (OpenVPN Connect, v2rayNG, V2RayN, V2RayU) проверены — все бесплатные/официальные, оставлены.

### 5. Усиление редиректа после логина
**Проблема:** в редких случаях после входа не было перехода на дашборд.

**Решение** — [`use-login.ts`](../src/ui/auth/hooks/use-login.ts)
- Добавлена «подстраховка»: если через 600 мс после редиректа страница всё ещё на `/login`, навигация принудительно повторяется. Покрывает редкий случай прерванной навигации, обычный поток не меняется.

### 6. Флоу сброса пароля — проверено (правки не требуются)
После проверки флоу уже корректен:
- Нумерация шагов: **Шаг 1/2/3 из 3** (email → код → пароль).
- Текст шага 1, одна строка на шаге 2, без дубля на шаге 3.
- Валидация пароля везде: 10+ символов, 1 заглавная, 1 строчная, 1 цифра, с подсказками и заблокированной кнопкой при невалидных данных.
- Ввод неверного кода больше не перекидывает на шаг 3 — код проверяется до перехода.

## ⏳ Осталось / временные решения

### Оплата (WATA, оплата картой) — пока НЕ реализована
- **Решение:** авторитетный контракт — `swagger.json`, и он по-прежнему описывает `POST /billing/checkout` как **заглушку 501** (идентичен `swagger-old.json` — отличий нет).
- **Временное решение (текущее поведение):** вызов checkout ловит `501`, и UI откатывается на **ручную оплату через Telegram**. Это сделано намеренно и уже подключено.
- **Что нужно для завершения:** бэкенд должен реально выпустить эндпоинт WATA и обновить swagger. Ожидаемый формат уже описан в заметке проекта:
  - `POST /api/v1/billing/checkout` тело `{ "plan": "monthly" }`, plan ∈ `monthly | quarterly | semiannual | annual`
  - ответ `{ payment_url, order_id, amount, currency, plan, duration }`
- **План после готовности бэкенда:** выбор тарифа → вызов checkout → редирект на `payment_url` → страницы возврата success/fail, которые перечитывают статус подписки.

### Что нельзя изменить со стороны фронтенда
- Реальные онлайн-платежи — заблокированы бэкендом (см. выше).
- Ссылка на Hiddify ведёт на GitHub проекта (как и у остальных клиентов), потому что точный App Store ID не удалось подтвердить без догадок.

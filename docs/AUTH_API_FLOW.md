# Auth API Flow

This project uses a two-step confirmation flow for operations that depend on email ownership. The frontend calls a prepare endpoint first, then routes the user to a confirm screen where the one-time code is submitted.

## Base URL

`API_BASE_URL` must include the backend API version prefix:

```env
API_BASE_URL=https://31232114dfsdf.api.dev.prometey.ink/api/v1
```

Frontend code then calls paths like `/auth/register`, not `/api/v1/auth/register`.

## Development Codes

The current shared development backend returns predictable manual test codes:

| Flow | Code |
| --- | --- |
| Register confirm | `111111` |
| Email change confirm | `999999` |
| Forgot/reset password | `555555` |

These are development fixtures only. Production should use real email delivery and one-time codes generated by the backend.

## Register

1. User submits email and password on `/register`.
2. Frontend calls `PUT /auth/register` with `{ email, password }`.
3. Backend creates a pending registration and sends a code to the email address.
4. Frontend moves to `/register/confirm?email=<email>`.
5. User enters the email code.
6. Frontend calls `POST /auth/register` with `{ email, code }`.
7. Backend confirms the account.
8. Frontend routes the user to `/login`.

For the shared dev backend, use `111111` on the register confirm screen.

## Forgot Password / Reset Password

1. User submits email on `/forgot-password`.
2. Frontend calls `POST /auth/forgot-password` with `{ email }`.
3. Backend sends a reset code to the email address.
4. Frontend moves to `/forgot-password/confirm?email=<email>`.
5. User enters the reset code.
6. Frontend moves to `/forgot-password/reset?email=<email>&code=<code>`.
7. User submits the new password.
8. Frontend calls `POST /auth/reset-password` with `{ email, code, new_password }`.
9. Backend updates the password.
10. Frontend routes the user to `/login`.

For the shared dev backend, use `555555` on the reset-code confirm screen.

## Email Change

Email change is an authenticated dashboard flow.

1. User is logged in and submits a new email from `/dashboard/profile`.
2. Frontend calls `PUT /auth/email` with `{ new_email }` and the access token.
3. Backend stores a pending email change and sends a code to the new address.
4. Frontend moves to `/dashboard/profile/email/confirm?email=<new_email>`.
5. User enters the email-change code.
6. Frontend calls `POST /auth/email` with `{ code }` and the access token.
7. Backend applies the new email.
8. Frontend returns to `/dashboard/profile?emailChanged=1`.

For the shared dev backend, use `999999` on the email-change confirm screen.

## Notes For Frontend Work

- Route files under `src/app` should stay thin and only compose page components from `src/ui`.
- Auth page composition lives in `src/ui/auth/pages`.
- Dashboard page composition lives in `src/ui/dashboard/pages`.
- Keep `/register/verify` and `/forgot-password/verify` available as backward-compatible aliases, but new flows should route to `/confirm`.
